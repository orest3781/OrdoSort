# UX audit — every screen (2026-09-30)

A second full pass, two days after `ux-audit-2026-09-28.md`, on `feature/media-loop` (v1.9.1 plus photos, GIFs and videos in the filing loop).

How it was done:
- **Screenshots:** every registered window rendered today (92 shots): light and dark at the default size, and light at 18px on the minimum size; every Settings and Box Labels Settings tab; the processing window with a PDF, a photo and a video.
- **Three read-only reviewers**, one per area (the filing loop and Settings; the rename and list tools; the PDF tools, labels and history). Each worked through the usual laws, keyboard use, screen-reader names, dark theme, 18px text and wording.
- **Every finding cites the code** and a concrete scenario. Both Criticals were also checked by hand.
- **Every open item from 2026-09-28** was checked against the current code (table at the end).

Not covered:
- The Edge and VLC panes can't be captured by the renderer, so what they show comes from the code alone.
- The label maker window wasn't rendered.

The patterns that repeat:
- **Text that ignores the text-size setting.** Captions, chips, the filed bar's file name and the name box stay at fixed sizes, so they get smaller than the body text at 18px.
- **Layouts that lose the main list at 18px on the minimum size.** This hits Standardise names, Bulk rename, List reformatter and Saved passwords.
- **Amber status lines for routine success** (UX-04, still open).
- **Tools that do the same thing in different ways:** stopping a run, marking failures, words for the same action, and what "nothing selected" means.
