# v1.0.0 Blockers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the four findings from `docs/superpowers/audits/2026-08-04-full-audit.md` that block cutting `v1.0.0` — non-atomic writes, the first-run zombie process, the lost audit row on exit, and Settings-OK clobbering a peer station.

**Architecture:** Five tasks.
```csharp
    /// <summary>Write via a sibling temp file, then replace — so an observer
    /// of <paramref name="fullPath"/> sees the complete old content or the
    /// complete new content, never a truncated or empty file. The previous
    /// File.WriteAllText truncated in place; a crash or a full disk in the
    /// gap destroyed a valid config, and on a shared config that took every
    /// station down until someone repaired it by hand (2026-08-04 audit 2.3).
    ///
    /// The temp file is a sibling, never %TEMP%: replace is only atomic
    /// within one volume, and the config can live on a share.</summary>
    internal static void WriteAtomic(string fullPath, string content)
    {
        var tmp = fullPath + ".tmp";
        // Encoding matches File.WriteAllText's default (UTF-8, no BOM), so
        // this change cannot alter a single byte of what lands on disk.
        File.WriteAllText(tmp, content);
        try
        {
            // File.Replace preserves the destination's ACLs and is the
            // strongest primitive Windows offers, but it REQUIRES the
            // destination to exist — hence the fallback for first creation.
            if (File.Exists(fullPath))
                File.Replace(tmp, fullPath, destinationBackupFileName: null);
            else
                File.Move(tmp, fullPath);
        }
        catch
        {
            try { File.Delete(tmp); } catch { /* best effort */ }
            throw;
        }
    }
```

### Task 2: `BoxLabelStore` cannot lose the box counters

**Audit finding 2.2 [V].** `BoxLabelStore.Mutate:126-128` treats empty content as `new BoxLabelsDoc()`, while `Read:44-51` throws `ConfigException` on the same input. The two disagree about what a 0-byte file means, and `Mutate` is the one that then truncates and rewrites (`:140-143`) — so a crash mid-write leaves 0 bytes, and the next station's box claim silently wipes every client's counter and reissues box numbers already printed on physical boxes.

**Task 1's fix does not apply here.** `Mutate` holds an exclusive `FileStream` (`FileMode.OpenOrCreate, FileAccess.ReadWrite, FileShare.None`) for the whole read-modify-write, and **that handle is the cross-station mutex**. Replacing the file would release and invalidate the lock other stations are contending on. So this task fixes the same class of bug by two different means: make a 0-byte state impossible to produce, and make it impossible to act on.

**Files:**
- Modify: `src/OrdoSort.Core/BoxLabelStore.cs:120-146`
- Create: `tests/OrdoSort.Core.Tests/BoxLabelStoreCorruptionTests.cs`

- [ ] **Step 1: Write the failing tests.**

```csharp
    /// <paramref name="timeout"/>. Returns false if it did not. Polls on the

    internal async Task<bool> WaitForIdleAsync(TimeSpan timeout)

    }
```
