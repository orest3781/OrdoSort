One question per screen: what is the one thing the user came here to do, and does the screen make it unmistakable, fast, forgiving, and well-ended? Each answer is scored against the cognitive laws that predict where people fail. This is a different lens from the August defect and chrome audits.

Six read-only sweeps, one per surface group, each required to cite file and line for every claim and to grep the tracker first; every Critical and Major was then re-read in source. A same-day QC pass by five further agents re-opened every citation, hunted for misses, and de-duplicated against the tracker: all 32 original findings stand, eleven details were corrected, one finding was narrowed, and six were added (UX-33 to UX-38). No live pass was run: every finding is a code path, so all carry [V]; the two whose consequence deserves a running app also carry [U] with the thing to measure.

What is already solid

QC verified every bullet against source; none was overstated.

  • The routing loop's feedback is proportional and inline. A route-coloured card below the buttons expires itself; a new arrival mid-session joins the queue with a note; Done says "N filed, M set aside" and claims a complete log only when true; Undo from Done re-enters Processing.
  • Every question dialog defaults to the safe answer, handles Esc once, uses verb labels, and all six Confirm call sites guard something genuinely irreversible. Nothing should be an undo instead.
  • Standardise names is the cleanest window in the app: the drop is the action, every row shows before → after with the refusal reason, Undo is scoped to what reverted, the date prompt remembers the last date.
  • Match and merge explains itself: bucket line and count-bearing buttons, so a disabled button is never unexplained.
  • Empty states are designed and tell "nothing here" from "nothing matches" in History, Filename list, Ready and Page counts.
  • Merge PDFs asks for the output location before the work, ships new file types off, and reports a missing Office app at drop time.
  • Unlock's wrong-password loop is inline, with "save it as…" right there; Zip promotes a typed password for the rest of the run.
  • The WebView2 failure messages are the model for error copy: they say what still works and what to install, and send the detail to the crash log. UX-33 is about the sites that do not follow them.
  • Keyboard focus is visibly distinct from hover on every control, and every tool window opens the same way.

UX-01ProcessingPeak-EndFixed 2026-09-05

A failed filing wipes the name the user just typed [V]

LoadCurrentAsync resets the box unconditionally (ShellViewModel.cs:1360). Both CommitError catches reload through it (:1436-1437, :1471-1477), and the session only advances on success, so the same PDF comes back with an empty box after the modal. Route buttons are enabled by route validity, not name validity, so an illegal name (Naming.cs:102, rewrapped at Commit.cs:103) or an unreachable folder reaches this path with the name typed. No test asserts the name survives.

Fix: keep TypedName when the document is unchanged (a "same document" refresh path). Pin: a commit that throws leaves TypedName intact — fails today.

UX-02Bulk renameZeigarnikFixed 2026-09-05

Sorting the preview breaks "next file needing a name" [V] [U]

PreviewGrid is sortable (no CanUserSortColumns="False"). The navigator reads a view-order index (BulkRenameWindow.xaml.cs:60-66, :128-137), walks Preview in insertion order (BulkRenameViewModel.cs:457-465), then indexes the view again. WPF sorts the view, never the source, so after any header click Enter or F2 opens an arbitrary row and seeds it, in the type-Enter rhythm the code designs for. Existing tests exercise the walk unsorted only.

Measure: sort by Result, press Enter on a stray, read which row opens. Fix: CanUserSortColumns="False", or navigate by row identity. Pin: with a sort applied, the row in edit has NeedsName — fails today.

UX-04Merge PDFsDohertyQC-corrected

An Office-document merge is one frozen status line, and the only way out is unlabelled [V]
